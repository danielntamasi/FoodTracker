# FoodTracker

iOS calorie and macro tracking app. Users add food entries via photo (AI vision), barcode scanning, or manual input. The app shows daily summaries, macro breakdowns, and history.

## Tech Stack

- **Language:** Swift, SwiftUI
- **Data:** SwiftData (single `FoodEntry` model)
- **Min Target:** iOS 17+ (SwiftData requirement)
- **Build:** Xcode project (no SPM dependencies)
- **No tests** currently
- **Orientation:** Portrait only (locked)

## Architecture Notes

- **Single model:** `FoodEntry` is the only SwiftData model. Fields: `id`, `name`, `calories` (per-serving), `proteinGrams` (per-serving), `carbsGrams` (per-serving), `fatGrams` (per-serving), `servings` (Double, default 1.0), `date`, `photoData`, `mealGroupID`, `mealName`, `notes`, `iconName`, `sortOrder`. Computed properties `totalCalories`, `totalProteinGrams`, `totalCarbsGrams`, `totalFatGrams` multiply per-serving values by `servings`. All display/aggregation uses `total*`; editing operates on per-serving values. Existing entries auto-migrate via SwiftData default (`servings = 1.0`). Meal grouping uses `mealGroupID` (shared UUID) + `mealName` fields, not relationships.
- **App Group:** `group.com.DNT.foodtracker` shared between main app and widget. `SharedConfig.swift` provides `appGroupID` and `sharedModelContainer`. `SharedHelpers.swift` provides `sharedDefaults` (UserDefaults suite). All UserDefaults access uses `sharedDefaults` (except `VisionProvider.selected` which uses `.standard`). `DailyTarget` reads/writes directly to `sharedDefaults`, so the widget sees target changes immediately. `FoodTrackerApp.init()` migrates legacy UserDefaults on first launch.
- **`foodIconName()`:** Free function in `FoodEntry.swift` that maps food names to SF Symbol icons via keyword matching. Mappings are a file-level `let` (not rebuilt per call).
- **Shared helpers:** `SharedHelpers.swift` contains pure utility functions: `servingPresets` (0.25–3.0x array), `formatServings()` (fraction characters), `formatMacro()`, macro calorie functions (`proteinCalories()`, `carbCalories()`, `fatCalories()`, `totalMacroCalories()`, `macroPercentages()`), `dominantColor(from:colorScheme:)` (CIAreaAverage extraction), `iconDarkColor(for:)` (hero background colors), `quickAddEntry/quickAddMealGroup` (ModelContext helpers), `DailyTarget.hasTargets`, `perServingFromPer100g()` (shared per-100g → per-serving conversion used by `PhotoAnalysisView` and `FoodAnalysisPipeline`). `SharedViews.swift` contains shared SwiftUI view components (`MetricPill`, `HeroMacroDonut`, `DailyGoalBarsView`, `CachedThumbnailImage`). `HeroPhotoSection.swift` contains the shared immersive hero layout (photo with gradient or icon-based gradient) used by `EditEntryView` and `MealSummaryView`.
- **Vision pipeline:** `FoodAnalysisPipeline.analyzeImage()` → vision provider identifies foods → USDA looks up macros (falls back to AI estimates). Defined in `FoodAnalysisService.swift`. Types/enums (`IdentifiedFood`, `VisionProvider`, `FoodAnalysisError`, etc.) live in `FoodAnalysisModels.swift`. `USDAService` actor lives in `USDAService.swift`. Vision prompt always groups multiple food items under a single `meal_name` with `ingredients` array; standalone items only returned for single-item photos.
- **Two vision providers:** Claude Sonnet 4.6 and Gemini 2.0 Flash, selectable in Settings. Provider config (including keychain accounts) lives in `VisionProvider` enum (`VisionProvider.selected` uses `UserDefaults.standard`, not `sharedDefaults`). Service actors: `ClaudeAPIService`, `GeminiAPIService`. Both send API keys via HTTP headers (not URL query params): Claude uses `x-api-key`, Gemini uses `x-goog-api-key`.
- **USDA service:** `USDAService` actor uses a user-provided API key from Keychain (account: `usda-api-key`), falling back to `DEMO_KEY` if none set. Free keys available at fdc.nal.usda.gov/api-key-signup (1,000 req/hr vs 30/hr). Single lookup method `lookupFood(for:)` returns `USDALookupResult` with better matching (fetches 5 results, scores by preferring "raw" and penalizing "dried"/"dehydrated"/"canned"/etc.), serving info extracted from `foodMeasures` → `servingSize` → detail endpoint `foodPortions` (3-tier fallback), and a `perServing` computed property that scales per-100g values by `servingGrams/100`. Used by `AddEntryView`, `EditEntryView`, and `FoodAnalysisPipeline`. Pipeline calculates `detectedServings = portion_grams / servingGrams` when USDA provides serving info, storing per-serving values with the servings count; falls back to treating detected portion as 1 serving when no serving info available. Query cleaned of parenthetical content to prevent API errors.
- **Barcode flow:** `BarcodeScannerView` → `OpenFoodFactsService` → presents results in `PhotoAnalysisView(foods:)`. Barcode items include per-100g nutrition data and serving size, enabling portion selection in the review screen. `IdentifiedFood` carries optional `caloriesPer100g`, `proteinPer100g`, `carbsPer100g`, `fatPer100g`, `servingGrams`, and `servings` fields for this purpose. `OpenFoodFactsService.Product` also includes per-100g fields.
- **Photo flow:** `PhotoCaptureView` → captures image → `PhotoAnalysisView(image:)` → runs `FoodAnalysisPipeline`. `PhotoUploadView` → photo library picker → same `PhotoAnalysisView` flow. Both use `ImagePicker(sourceType:)` which accepts `.camera` (default, falls back to `.photoLibrary` on Simulator) or `.photoLibrary`.
- **PhotoAnalysisView dual init:** `init(image:)` for photo analysis, `init(foods:)` for barcode/pre-resolved results. Barcode/label items with per-100g data get a `portionPicker` (same 0.25–3.0x scrollable presets + custom field as `AddEntryView`); `applyServings()` recalculates all macros from per-100g base values. `saveAll()` stores the photo thumbnail only on the first entry of each meal group to avoid duplicate blob storage; `FoodEntryRow` accepts an optional `groupPhotoData` parameter so expanded sub-items inherit the group's photo for display.
- **Custom tab bar:** `ContentView` uses a `ZStack` with a floating `HStack` tab bar (`.ultraThinMaterial`, `RoundedRectangle(cornerRadius: 24)`) instead of stock `TabView`. Center "+" button toggles a radial arch menu overlay with 5 options (Recent, Manual, Photo, Upload, Barcode) that fan out in an arc above the button with staggered spring animations. Items are placed via `.overlay` on the + button (so they animate outward from it) with horizontal correction via `layoutWidth` GeometryReader so they land centered on screen despite the button being offset in the HStack. Uses `AppTab` enum for tab state, `QuickAddAction` enum (`.photo`, `.barcode`, `.manual`, `.browse`, `.uploadPhoto`) for action routing. Plus button rotates 45° (becomes X) when menu is open. Dimming backdrop dismisses on tap. `ScaleButtonStyle` provides press animation for the "+" button. Add-entry sheets live in `ContentView`, not `DailySummaryView`.
- **Browse foods:** `BrowseFoodsView` (in `BrowseFoodsView.swift`) shows top 5 frequent foods (by all-time add count, dynamically ranked) and 10 recent unique foods from previous days. Tapping a food creates a new `FoodEntry` with `servings: 1.0` explicitly set and dismisses. Accessed via "Recent" in the radial menu.
- **DailySummaryView layout:** Uses `List` with `.listStyle(.plain)` and `.scrollContentBackground(.hidden)` for card-style layout with native swipe actions. Summary card wrapped in glassmorphic background (`secondarySystemGroupedBackground`, cornerRadius 16, subtle shadow). Food entries in individual cards (cornerRadius 12). Time-of-day section headers have tinted icon circles. Custom empty state with `symbolEffect(.pulse)`. Swipe actions (all trailing): delete (red, destructive), edit (blue), add-again (green). Cross-section drag-to-reorder via `FlatListItem` enum (`.sectionHeader`, `.entry`, `.expandedSubItem`) flattened into a single `ForEach` with `.onMove`; section headers and expanded sub-items are `.moveDisabled(true)`. `moveItems(from:to:)` walks the reordered flat list to find each entry's nearest preceding section header; if section changed, `adjustedDate(for:movingTo:)` updates the entry's hour (Morning→9, Afternoon→13, Evening→18, preserving day/minute/second). All 3 section headers always shown (empty ones at 50% opacity as drop targets). `assignInitialSortOrders()` ensures all entries have stable sortOrder values. `coloredMacroText()` free function renders colored inline macro text (blue P, orange C, purple F) used by both `FoodEntryRow` and `MealEntryRow`. Animated numbers via `.contentTransition(.numericText())` on calorie counts and macro values in `MacroDonutCard`, `MacroProgressLabel`, and `MacroLabel`. Meal group rows have a chevron button toggling `expandedGroups: Set<UUID>` to show/hide individual entries inline. Tapping a meal group row opens `MealSummaryView` (immersive detail sheet). Widget data synced reactively via `.task(id: widgetSyncID)` whenever totals change, calling `syncWidgetData()` → writes to shared UserDefaults + `WidgetCenter.shared.reloadAllTimelines()`.
- **Serving selector:** `AddEntryView` and `EditEntryView` both include a serving multiplier (0.25–3.0x) with scrollable preset capsule buttons, custom text field, and total summary. User enters per-serving values; `servings` is persisted on `FoodEntry` and computed `total*` properties handle multiplication. `EditEntryView` loads `entry.servings` on edit and saves it back (no manual multiplication). Uses shared `formatServings()` from `SharedHelpers.swift`.
- **Auto-capitalization:** All food name `TextField`s use `.textInputAutocapitalization(.sentences)` — applies in `AddEntryView`, `EditEntryView`, and `PhotoAnalysisView` (meal names, ingredient names, standalone names).
- **DailySummaryView components:** `FoodEntryRow` (`CachedThumbnailImage` for async-decoded 52×52 thumbnails, colored macros), `MealEntryRow` (same), `MacroLabel`, `MacroDonutCard` (animated numbers, shows "X left/over"), `MacroProgressLabel` (animated numbers + progress bar). Uses `TimeOfDay` enum (with `tintColor`, `startHour`, `defaultHour`) for Morning/Afternoon/Evening sections, `EntryDisplayItem` enum for grouping logic, and `FlatListItem` enum (`.sectionHeader`, `.entry`, `.expandedSubItem`) for the flattened drag-reorder list. `groupedDisplayItems()` free function uses `Dictionary(grouping:)` for O(n) meal group assembly, reused by `HistoryView`. Performance: `totals` computed property does a single-pass reduce for all macros; `entriesByPeriod` buckets entries by time-of-day in one pass (avoids 3x filter). Reverse chronological toggle (arrow button) persisted in `sharedDefaults`. `FoodIconThumbnail` view renders a colored SF Symbol in a rounded rect background (used when no photo); `foodIconColor(for:) -> Color` free function maps icon names to colors. `MealGroup: Identifiable` struct (id, name, entries) used for sheet presentation.
- **MealSummaryView:** (in `MealSummaryView.swift`) Immersive full-screen sheet opened when tapping a meal group (in both `DailySummaryView` and `HistoryView`). Uses `HeroPhotoSection` for the photo/icon hero layout, shows ingredient list, `DailyGoalBarsView` (when targets set), formatted timestamp. Uses shared `dominantColor()` and `iconDarkColor()` from `SharedHelpers.swift`.
- **Widget:** `FoodTrackerWidgetExtension` — `.systemMedium` widget showing donut chart with calories left + macro progress bars. Uses `TimelineProvider` that reads from shared SwiftData store and App Group UserDefaults. Refreshes every 15 min. No-target fallback shows simple large calorie number + P/C/F labels instead of donut. Reads `widgetLastSync` timestamp to zero out values if data is from a previous day (prevents stale display).
- **DailyTarget:** UserDefaults wrapper in `SettingsView.swift` for calorie/macro targets (uses `sharedDefaults`). `DailyTarget.hasTargets` static computed property (in `SharedHelpers.swift`) replaces duplicate checks across views.
- **HistoryView collapsible days:** `expandedDays: Set<String>` controls which date sections are expanded. All days start collapsed by default. Section headers are tappable `Button`s with chevron, calorie count, and `coloredMacroText` for macros.
- **SourceBadge:** View in `PhotoAnalysisView.swift`.
- **EditEntryView:** Immersive hero sheet layout using `HeroPhotoSection` — full-bleed photo (65% height) with gradient fade to dominant color (extracted via `CIAreaAverage`), or icon-based gradient hero when no photo. Read mode shows food name, metric pills (via `HeroPhotoSection`), macro donut chart with percentage breakdown, `% of Daily Goal` bars (when targets set), formatted timestamp. Floating capsule buttons ("Edit"/"Done"/"Cancel") overlay the hero instead of toolbar. Edit mode replaces hero with custom grouped form sections on `.ultraThinMaterial`-style dark background: FOOD (name with inline lookup icons, calories), MACROS (protein/carbs/fat — per-serving values), SERVINGS (preset capsules 0.25–3.0x, custom field, total preview), DATE & TIME (`DatePicker` with `.date` + `.hourAndMinute`). Inline lookup icons (sparkles for AI lookup, barcode.viewfinder for scan) appear only when `nameChanged` (entry.name != originalName); `lookupError` shown inline in FOOD section. `finishEditing()` saves `entry.servings = servings` (no manual multiplication — computed `total*` properties handle it). Snapshots original values (including date and servings) on edit; Cancel restores all originals, Done title-cases and updates iconName.
- **EditEntryView barcode scan:** `EditBarcodeScannerView` (in `EditEntryView.swift`) is a lightweight barcode scanner that returns `OpenFoodFactsService.Product` via a callback, updating the entry's name/calories/macros directly. Uses `BarcodeCameraView` from `BarcodeScannerView.swift`.
- **Title casing:** `String.titleCased()` extension (in `FoodAnalysisModels.swift`) is applied at all entry creation points: `FoodAnalysisPipeline` (vision), `PhotoAnalysisView.saveAll()`, `AddEntryView.save()`, `EditEntryView.finishEditing()`, `OpenFoodFactsService` (barcode). One-time migration in `FoodTrackerApp` fixes historic entries' `name` and `mealName` fields (UserDefaults key: `didMigrateEntryNameCasing`).
- **Performance tile:** `PerformanceTileView` (in `PerformanceTileView.swift`) shows adherence-focused stats with `PerformancePeriod` enum (week/month/year) segmented picker. "On target" = all macros with targets set are within ±10%; days with no entries are excluded from totals. Week view has two modes toggled by a button in the header (`useBarChart` state, defaults to bar chart): **Bar chart mode** shows a 7-day `BarMark` chart (Swift Charts) with each bar colored by `dayOverallStatus` (green/yellow/red/gray), a dashed `RuleMark` at the calorie target, and a row of small status dots below; **Classic mode** shows the original 7×N dot matrix (rows = Cal/Pro/Carb/Fat, columns = days). Toggle icon switches between `chart.bar.fill` and `circle.grid.3x3.fill`. Both modes share the hero stat ("X of Y on target" + adherence %), avg calorie delta, and current streak footer. `dayOverallStatus(_:)` returns a `DotStatus` for the whole day by checking the worst macro deviation. Month: hero stat + 4 weekly adherence dots (W1–W4, colored green/yellow/red by weekly adherence using same thresholds as year monthly dots) + avg cal/day vs target + trend arrow (vs previous 28 days) + best streak. Year: hero stat + 12 monthly adherence dots + best streak. No-targets fallback: week shows logged-day dots, month shows 4 weekly dots (accent/gray), year shows monthly dots + avg cal/day + days logged. Performance thresholds defined as named constants in `PerformanceThresholds` enum. `buildDailyRecords()` pre-buckets entries by day for O(n + d) efficiency. `PerformanceInfoView` (in `PerformanceInfoView.swift`) explains dot colors, weekly matrix, and stats. Uses `MacroType`, `DotStatus`, `DayRecord`, `TrendDirection` enums/structs.
- **User preferences** stored via App Group `UserDefaults` (daily targets, sort order) and `UserDefaults.standard` (vision provider selection) and Keychain (API keys for vision providers and USDA). Keychain items use `kSecAttrAccessibleWhenUnlockedThisDeviceOnly` to prevent iCloud sync.

## Conventions

- Commit messages: imperative mood, short description of change (e.g., "Fix photo capture not dismissing after saving food entries")
- No external dependencies — everything is built with Apple frameworks
- API keys are never hardcoded; stored in Keychain, entered via Settings
- **Always update CLAUDE.md before committing** to reflect any structural or architectural changes made during the session (new files, new model fields, new types, changed flows, etc.)

## Building

Open `FoodTracker.xcodeproj` in Xcode and build for iOS Simulator or device. Camera features require a physical device. The app requires `NSCameraUsageDescription` (set in Info.plist or Xcode target settings).

**Widget setup:** After opening the project, select both the FoodTracker and FoodTrackerWidgetExtension targets, go to Signing & Capabilities, and add the App Groups capability with identifier `group.com.DNT.foodtracker`.
